# Оружие и щиты

Статус — выполнено, проверено пользователем в игре 25 ноября 2026.
Цель текущего этапа — сверить игровые ID, подготовить поимённые списки операций и план. Граница этапа — анализ серверного datapack и поставляемого клиента.
Ожидаемый результат реализации — равенство каталогов, отдельные административные мультиселлы по назначению, типу, виду и магическому признаку, уникальные текстуры, отсутствие розничной вставки СА и её вариантов оружия.
Приёмка — сравнение множеств ID, проверка ссылок, примерка в клиенте и открытие каждого списка администратором.
Открытый вопрос — выбор сохраняемого ID при совпадении текстур и различии характеристик, назначения или геометрии.

## Итоговая карта операций

[[Задачи/Итоговая таблица оружия и щитов.tsv|Итоговая таблица]] задаёт действие для каждого из 1384 исходных ID. Она имеет приоритет над предварительными списками ниже. Сохранение отдельного ID при конфликте — предлагаемое решение для сохранения механики. Физическое объединение таких пар потребует отдельного решения по указанным различиям.

|---|---:|---|
| Оставить | 519 | Сохранить шаблон и клиентское отображение. |
| Сохранить отдельный ID | 219 | Сохранить предмет и его привязки. Для выдачи через GM использовать колонку представителя текстуры. |

| Удалить СА | 436 | Убрать вариант и механизм установки. Для существующего экземпляра указан конечный базовый ID. Удалить обмены установки и снятия, проверить сохранность заточки и аугментации. |

Для СА выявлены ещё 25 вариантов помимо 411 результатов обмена: это записи с названием эффекта в клиентском поле add_name и однозначной базой по названию. Например, Halberd – Critical Stun 4861 → Halberd 98. Для Angel Slayer принята база 6367. Для GM-представления текстур Nightmare Shield и Angel Slayer предложены 2498 и 6367. ID в колонке GM используется только для витрины. Перенос экземпляров допустим только по колонке «Конечный ID замены».

**Приёмка таблицы.** Каждый исходный ID встречается один раз; у пяти объединений и 436 вариантов СА заполнен существующий конечный ID, который сохраняется. Для теневых и клиентских удалений замена пуста. Перед применением сверить карту со свежими DAT, шаблонами и БД, проверить зависимости по приложениям к задаче, затем выполнить игровые проверки из плана. Текущая поставка содержит ТЗ и данные аудита.

## Результат сверки и списки операций

Проверены шаблоны build/aCis_datapack/data/xml/items и непосредственно декодированный client/build/system/weapongrp.dat. У client/source и client/build совпадает SHA-256 этой таблицы. В серверном каталоге 1313 ID оружия и щитов, в клиентской таблице 1384. Все серверные ID представлены. Из 95 щитов 44 имеют отдельные наборы текстур, 45 предлагается объединить, 6 теневых щитов удалить.

[[Задачи/Реестр оружия и щитов.tsv|Реестр операций]] содержит строку на каждый ID. Фильтр «Операция» даёт списки на сохранение (519), объединение (249), удаление теневых предметов (123), удаление СА (411), удаление только в клиенте (71) и ручную проверку (11). В колонке предлагаемого ID для СА указана база рецепта, для дубля — наименьший серверный ID без СА с тем же упорядоченным набором текстур. Это предложение для миграции. Модель и список NPC рядом позволяют проверить последствия. Отсутствие записи в weapongrp сейчас устранять не требуется.

**Проверка за пределами этого XML-реестра.** До правок для каждого утверждённого ID проследить Java-константы, массивы и диапазоны в квестах, наградах, AI, обработчиках предметов и конфигурации. Проверить условия входа и завершения квестов, обмен и изъятие вещей. Числа сверять с назначением поля (ID предмета, навыка, NPC, рецепта или списка). Пример отдельной проверки — AI Gordon обращается к 8190 и 8689 напрямую; оба проклятых оружия сейчас сохраняются. Для замены проверить также свойства шаблона, которыми пользуются механики без явной ссылки на ID: грейд, ограничения класса и питомца, заточка, кристаллизация, заряды, инкрустация, экипировочные навыки и боевые характеристики.

**Сохранённое состояние.** До применения запросить фактические количества по ID на копии рабочей БД. Проверить items во всех местах хранения и items_on_ground, остатки магазинов, офлайн-покупку и продажу, изученные рецепты. Различать ID шаблона и ID экземпляра: augmentations.item_oid ссылается на экземпляр. При замене сохранить object ID и проверить совместимость аугментации и ярлыков; при физическом удалении экземпляра убрать зависимые записи. Проверить режим поля item в офлайн-торговле по коду загрузки. Испытать вход, склад, подбор, торговлю и повторный запуск миграции.

**Критерий приёмки.** Для каждого выбывшего ID составить конечное решение по каждой привязке: убрать источник получения, заменить предмет или удалить зависимый рецепт/предложение целиком. После сборки повторить скан поставляемых XML, SQL, Java/скриптов и конфигов, декодировать обе таблицы itemname, weapongrp и зависимые клиентские таблицы, проверить мигрированную БД. Должно остаться ноль действующих ссылок на выбывшие ID и ноль записей, позволяющих повторно получить их после рестарта. Общий ресурс текстуры сохраняется, пока им пользуется другой предмет или NPC.
