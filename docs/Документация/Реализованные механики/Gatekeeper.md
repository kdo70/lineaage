# Gatekeeper

## Назначение

GlobalGatekeeper — глобальный телепортёр с меню из XML, динамическими ценами, задержкой телепорта и вкладкой популярных направлений. Перенесён из `C:\a1_l2j` в рабочую сборку `D:\Lineage\build` 2026-11-23. Содержит одно меню, 175 точек назначения и привязки к 18 NPC.

Рабочие изменения находятся в `build\aCis_gameserver` и `build\aCis_datapack`. Каталог `D:\Lineage\source` при переносе не изменялся.

## Файлы и устройство

Пути в таблице указаны относительно `D:\Lineage\build`.

| Файл или каталог | Назначение |
| --- | --- |
| `aCis_gameserver\config\mods\gatekeeper.properties` | Поведение, цены, задержка, пагинация |
| `aCis_datapack\data\xml\gatekeeper.xml` | ID NPC, меню, вкладки, области, координаты, ограничения, подписи и оформление |
| `aCis_datapack\data\html\script\teleport\GlobalGatekeeper` | Шаблоны `areas.htm`, `locations.htm`, `popular.htm`, `intro.htm`, `info.htm`, `pk.htm` |
| `aCis_datapack\data\xml\scripts.xml` | Регистрация `script.teleport.GlobalGatekeeper` |
| `aCis_datapack\sql\gatekeeper_stats.sql` | Схема статистики для новой базы |
| `tools\gatekeeper\migrate.sql` | Создание таблицы в существующей базе без удаления данных |
| `tools\gatekeeper\check.ps1` | Повторяемая Java-проверка загрузки данных |

Java-классы находятся в `aCis_gameserver\java\net\sf\l2j`:

- `gameserver\scripting\script\teleport\GlobalGatekeeper.java` — диалоги, обработка команд и телепортация.
- `gameserver\data\xml\GatekeeperData.java` — загрузка XML и расчёт цен.
- `gameserver\data\manager\GatekeeperStatsManager.java` — счётчики и рейтинг направлений.
- `gameserver\model\gatekeeper` — модели меню, вкладок, областей, точек и таблиц.
- `gameserver\enums\GatekeeperPointType.java`, `GatekeeperTabType.java` — типы точек и вкладок.

Настройки загружаются через `Config`; данные и статистика инициализируются в `GameServer`. `Shutdown` сохраняет счётчики, `AdminReload` перезагружает XML телепортов.

Скрипт перехватывает первый диалог зарегистрированных NPC. Команды `List`, `Area`, `Popular`, `Page`, `Tp` передаются через `Quest GlobalGatekeeper`. Выбор назначения ограничен точками меню конкретного NPC.

## Настройки

| Параметр | Значение после переноса | Поведение |
| --- | --- | --- |
| `RowsPerPage` | 12 | Строк на странице |
| `PopularLimit` / `PopularMinCount` | 20 / 1 | Размер списка популярных точек и порог попадания |
| `TeleportDelay` | 5000 мс | Анимация перед телепортом; 0 отключает, максимум 60000 |
| `DefaultPriceId` | 57 | Валюта по умолчанию: адена |
| `DefaultPrice` / `DefaultNoblePrice` | -1 / -1 | Расчёт цены по формуле; 0 задаёт бесплатный телепорт |
| `PricingEnabled` | True | Динамическое ценообразование |
| `PriceRounding` | 100 | Шаг округления |
| `NearPrice` / `FarPrice` | 15000 / 100000 | База по расстоянию |
| `RefDistance` / `DistanceCurve` | 240000 / 1.35 | Опорное расстояние и показатель степени |
| `CapPrice` | 200000 | Потолок базы по расстоянию |
| `LevelPriceFrom` / `LevelPriceTo` | 1 / 80 | Диапазон изменения коэффициента уровня |
| `LevelPriceMinRate` | 0.4 | Коэффициент на минимальном уровне |
| `KarmaPriceCap` / `KarmaPriceRate` | 10000 / 1.0 | Карма для максимальной надбавки и её величина |
| `NightPriceRate` | 1.25 | Множитель игровой ночи |

Модификаторы расстояния, уровня, кармы и ночи включены отдельными параметрами `DistancePriceEnabled`, `LevelPriceEnabled`, `KarmaPriceEnabled`, `NightPriceEnabled`.

Цена строится из базы, коэффициентов уровня, кармы и ночи с округлением до `PriceRounding`. База берётся из явной цены точки либо рассчитывается по расстоянию. Детали наследования цен и примеры описаны комментариями в `gatekeeper.properties` и `gatekeeper.xml`.

## Ограничения и статистика

Перед списанием валюты проверяются состояние персонажа, Noblesse для точек NOBLE, допустимый уровень и осада замка назначения. Телепорт запрещён мёртвому персонажу, при торговой операции, в режиме Олимпиады или наблюдателя, при участии в фестивале и с проклятым оружием.

Во время задержки действует отдельная блокировка движения Gatekeeper, не снимающая блокировки других механик. Запрос регистрируется атомарно до завершения операции. Перед переносом повторно проверяются online, смерть, торговля, Olympiad, observer, festival, cursed weapon, уровень, Noblesse и осада. Цена фиксируется при запросе и списывается после задержки и проверок. При отмене или выходе до завершения оплата не списывается; нехватка валюты отменяет перенос.

Таблица `gatekeeper_stats` хранит `loc_id`, `teleport_count`, `last_used`. Счётчики загружаются при старте, обновляются в памяти и сохраняются каждые пять минут и при штатном завершении. Рейтинг кешируется на 30 секунд. Аварийная остановка может потерять ещё не сохранённые счётчики. Историческая статистика старого проекта не переносилась.

## Сборка и обновление

Из `D:\Lineage\build`:

```powershell
.\compile.ps1
.\tools\gatekeeper\check.ps1
```

Ожидается `BUILD SUCCESSFUL`, затем `PASS` проверки настроек, 18 привязок NPC, 175 точек, ограничения списка направлений и перезагрузки XML.

В Ant-сборке включено копирование `**/*.properties`, чтобы конфиг из `config\mods` попадал в `dist\gameserver\config\mods`.

Новая Docker-база получает таблицу из SQL датапака. Для существующей базы требуется однократное применение `tools\gatekeeper\migrate.sql`; локально оно уже выполнено. Установщики `.bat` и `.sh` также включают схему Gatekeeper.

После сборки обновить локальные серверы:

```powershell
docker compose up -d --build login game
docker compose ps
docker compose logs --tail 150 game
```

Команда GM `//reload teleport` перечитывает данные телепортов. При изменении списка NPC дополнительно требуется `//reload script`, чтобы зарегистрировать новые ID. Изменения конфигурации безопаснее применять перезапуском; правки HTML требуют обновления кеша или перезапуска согласно настройкам кеширования.

## Разметка 2026-11-24

Итоговый вид проверен пользователем в игровом клиенте.

- Окно: 480×400 пикселей; ширина таблиц: 450 пикселей, рядом с полосой прокрутки.
- Все шесть вкладок размещены в одну строку (`tabColumns=6`).
- Вкладки, шапка таблицы и обычные строки имеют одинаковую высоту 22 пикселя.
- Для удобства игроков заголовки переведены на русский: Локация, Точка (Столица в списке областей), Цена, Валюта, Ур.
- Location показывает название локации, Point — отдельную точку назначения; Capital сохраняет ссылку на столицу.
- Price содержит только сумму, Item — полное серверное название предмета оплаты. Подтверждение сохраняет полное направление и валюту.
- Обрезка названий отключена (`maxChars=0`), длинные значения могут переноситься. Исправлено записанное в XML сокращение Talking Island.
- Заполнение страниц до 390 пикселей поддерживает постоянную полосу прокрутки; сохранены вертикальные отступы перед списками.

Проверки: полная сборка, загрузка 175 точек для 18 NPC и повторная загрузка XML прошли успешно. Изменения применены к локальному серверу, подтверждена регистрация Bartz. Проверка интерфейса не заменяет проверку оплаты и игровых ограничений.


## Проверка безопасности — 2026-11-24

Изолированная Java-проверка: build/tools/gatekeeper/GatekeeperSecurityCheck.java. Метод completeTeleport скопирован из текущего рабочего исходника без изменений; Player, Castle и пакеты заменены тестовыми зависимостями. Проверка не запускает игровой сервер и не имитирует сеть.

| Сценарий на момент завершения задержки | Результат |
| --- | --- |
| Смерть | PASS: нет оплаты и переноса |
| Offline | PASS: нет оплаты и переноса |
| Запрещённое состояние | PASS: нет оплаты и переноса |
| Недоступность точки (уровень/Noblesse) | PASS: нет оплаты и переноса |
| Началась осада | PASS: нет оплаты и переноса |
| Валюты меньше стоимости | PASS: баланс не изменён, переноса нет |
| Достаточно валюты | PASS: одно списание, один перенос |
| 10000 параллельных регистраций одного ID | PASS: один победитель; после удаления ID повторная регистрация успешна |

Ограничения: тест регистрации проверяет используемый ConcurrentHashMap.newKeySet().add(), а не полный сетевой обработчик. Запрещённые состояния объединены тестовой зависимостью; уровень и Noblesse представлены результатом isAvailableFor. Полный жизненный цикл logout, смерть с последующим воскрешением до таймера, смена состояния между последней проверкой и переносом, сетевой спам и фактическое снятие блокировки движения требуют отдельной интеграционной проверки. finally освобождает блокировку и регистрацию после завершения задачи; это проверено чтением исходника, не игровым клиентом.

Сборка Ant успешна (2361 Java-файл); Docker-образ обновлён, db/login/game healthy, Bartz зарегистрирован. Игровые проверки клиентом после обновления не выполнялись.
