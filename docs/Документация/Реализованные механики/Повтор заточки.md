# Повтор заточки

Перенесена старая функция повторной заточки, чтобы применять свитки без повторного выбора предмета. Источник: `C:\a1_l2j`; исходный проект не изменён.

## Поведение и настройка

- «Заточить» выполняет одну попытку и закрывает окно; «Повторить» при успехе сохраняет окно и подсветку цели.
- Неудача, включая благословенный свиток, окончание свитков или предел заточки завершают повтор. Следующий свиток берётся только того же item ID.
- Если выбранный предмет отсутствует в инвентаре, сервер отменяет попытку, закрывает окно и отправляет `INAPPROPRIATE_ENCHANT_CONDITION`; свиток не расходуется.
- `EnchantKeepWindowOpened = True` в `build/aCis_gameserver/config/players.properties`; применяется после перезапуска. Значение по умолчанию в коде — `false`. Нужен изменённый клиент Interlude.
- Шансы, ограничения и последствия заточки не изменены. Автоматической серии нет.

## Реализация

Сервер: `Config.java`, `RequestEnchantItem.java`, `players.properties` в рабочем `build/aCis_gameserver`. После успеха сервер отправляет обновление инвентаря до `ChooseInventoryItem`, чтобы уровень предмета не отставал. Только явная отмена с object ID `-1` обрабатывается без лишнего сообщения.

Клиент: `client/build/system/interface.u` и `interface.xdat`; исходник окна — `tools/client/Interface/Classes/ItemEnchantWnd.uc`. Цель запоминается по ServerID и отмечается текстурой; повторные нажатия блокируются на время ответа. Подпись задаётся через Unicode-коды в OnLoad; штатные ID подписи кнопки отключены значением `-9999`.

Сборка: `tools/client/build_interface.ps1`, упаковка — `pack_l2_package.ps1`. XDAT: `add_repeat_button.groovy` и `repeat_caption.groovy` с библиотеками `tools/vendor/xdatEditor`. Резервные копии клиента: `interface.u.before-repeat.bak` и `interface.xdat.before-repeat.bak`. Редактировать только рабочий клиент.

## Проверки и ограничения

2026-11-24: сервер и интерфейс собраны, все 727 импортов интерфейса разрешаются; из 142 классов изменён размер только ItemEnchantWnd. Локальный GameServer запущен и зарегистрирован, контейнеры healthy. Пользователь подтвердил работу, подпись без артефакта и обработку выброшенного предмета.

После подтверждения выполнен статический анализ изменённых ветвей и связанных механизмов: очередь GameClient сериализует запросы, расход свитка проверяется инвентарём под блокировкой, сохранены проверки владельца и условий заточки. Новых уязвимостей не выявлено; нагрузочные и специально сформированные сетевые запросы отдельно не тестировались.

Клиент ожидает продолжение до 400 мс после результата, затем закрывает окно. Существующий протокол не различает кнопки на сервере и не содержит уникального ID попытки: каждый допустимый запрос считается отдельной попыткой с расходом свитка.
