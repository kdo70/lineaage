# Свечение оружия и dev-инструмент

Добавлена настройка положения и размера свечения в работающем клиенте, чтобы подготовить параметры для последующего переноса в DAT. Рабочий клиент: `D:\Lineage\client\build`. Ярлыки `Lineage II.lnk` и `Lineage II Dev.lnk` запускают обычный режим и dev-инструмент соответственно.

Оставлены `LineageEffect.c_u...`, удалены 753 ссылки `LineageWeapons.rangesample`. Для 520 дополнительных ID назначены эффекты по моделям и A/S-аналогам; 13 ретейльных исключений Akamanah, Zariche и Infinity не изменены.

## Управление

Инструмент автоматически определяет оружие своего персонажа. Удерживать `Ctrl+Shift`: `Z/X`, `C/V`, `B/N` — XYZ, `G/H` — размер, `S` — сохранить, `R` — сброс. Крупный шаг включается в окне. Парные эффекты связаны зеркально. Сброс возвращает исходные параметры этого оружия, а для сохранения сброса на следующие запуски нужно нажать «Сохранить».

## Куда пишет «Сохранить»

**Основной файл для будущей задачи переноса:** `D:\Lineage\tools\client\glow-mesh\effect-positions.json`.

Кнопка «Сохранить» и `Ctrl+Shift+S` записывают туда параметры текущего ID оружия. JSON в UTF-8, ключ — строковый ID из `weapongrp`, значение — два массива: основной и второй эффект. Каждый массив содержит **`[X, Y, Z, scale, velocity]`**. `scale` — размер, `velocity` — скорость частиц, сохраняемая вместе с остальными параметрами. Повторное сохранение заменяет запись этого ID, остальные записи сохраняются; файл заменяется через временный `.tmp`.

Файл уже содержит пользовательские настройки; при дальнейшей работе состав меняется. Изменение в dev-окне само по себе ещё не является постоянным сохранением. Для будущей задачи читать актуальный файл, а не копию из старого отчёта.

Связанные файлы в `D:\Lineage\tools\client\glow-mesh`:

- `catalog.json` — имена эффектов, модели, исходные параметры и наличие второго эффекта; нужен для сопоставления сохранений с оружием.
- `effect-session-cache.json` — последние XYZ и размер по имени эффекта для текущей сессии. Автоматически применяется к оружию с тем же эффектом; при новом запуске очищается. Это не замена `effect-positions.json` и не список подтверждённых настроек всех ID.
- `prepared.txt`, `original.ddf`, `prepared.dat` — подготовленная базовая таблица и определение её формата.
- `weapongrp.original.dat` — резервная таблица до изменений свечения; `effect-assignments.json` — назначения недостающих эффектов и их доноры.
- `live-session.jsonl`, `live-error.txt` — диагностика, не источник настроек для переноса.

## Перенос настроек в клиент

Настройки 368 предметов из `effect-positions.json` перенесены в клиентский `weapongrp.dat`, чтобы свечение работало в обычном режиме. `glow_mesh.py bake` собирает файл на базе `prepared.txt` и сверяет его обратным чтением с учётом точности float32. Для двух моделей порядок полей: XYZ обоих эффектов, оба масштаба, обе скорости.

## Реализация и проверки

Инструменты: `D:\Lineage\tools\client\glow_mesh_live.py`, `glow_effect_logic.py`, `glow_effect_assignment.py`, `glow_mesh.py`, `create_glow_shortcuts.ps1`. Dev-патч меняет только память запущенного им клиента; `engine.dll` на диске не переписывается. Привязан к проверенной версии движка и требует повышения прав Windows.

Поставляемые файлы: `build/client-patch/system/weapongrp.dat` и архив исходников/базовых данных `build/client-patch/glow-editor.zip`. Архив содержит пути относительно `D:\Lineage`; исполняемые инструменты используются из `D:\Lineage\tools`, зависимости — из существующих `tools/vendor` и `tools/python`. Постоянные пользовательские сохранения в архив не включены, актуальный источник указан выше.

Пользователь подтвердил работу. Пройдены проверки кэша, сброса, зеркальности, размера, 12 x86-сценариев и сверка 732 строк DAT с исключениями. После подтверждения проверены границы записи, запуск своего процесса, сигнатуры движка и разделение постоянных настроек/кэша; новых уязвимостей в проверенном коде не выявлено. Привязка к версии движка остаётся ограничением; полномасштабный динамический аудит клиента не проводился.
