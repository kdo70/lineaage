# Размер NPC-диалогов с сервера

Размер можно задавать непосредственно в конкретном HTML-файле датапака:

```html
<!-- dialog-size: 800x600 -->
<html><body>
Содержимое диалога
</body></html>
```

Комментарий допускается в любом месте файла; удобнее размещать его перед `<html>`. Размеры десятичные, ширина × высота. Пробелы и регистр не важны. Обрабатывается первая директива, все такие комментарии удаляются перед отправкой клиенту. Недопустимое значение игнорируется с предупреждением в логе. HTML без директивы использует стандартный размер. Если Java-код вызывает `setWindowSize`, этот размер имеет приоритет независимо от порядка вызовов `setHtml`/`setFile`. Изменения файлов требуют обновления HTML-кеша или перезапуска сервера согласно текущей настройке кеширования. Клиентский патч остаётся прежним.

Для проверки под GM выполните `//test dialog 800 600`. Тестовый диалог содержит ссылки для переключения на 500×350 и стандартный размер, а также 40 строк для проверки прокрутки. Команда использует существующий доступ `admin_test` (уровень 7).

Сервер задаёт внешнюю ширину и высоту окна в пикселях интерфейса:

```java
NpcHtmlMessage html = new NpcHtmlMessage(npc.getObjectId());
html.setFile("data/html/default/1.htm");
html.setWindowSize(800, 600);
player.sendPacket(html);
```

Допустимые размеры: ширина 200–1920, высота 120–1080. Для небольшого разрешения экрана выбирайте меньшие размеры. Без вызова `setWindowSize` клиент восстанавливает исходные размеры. Размер HTML-области автоматически равен ширине окна минус 14 и высоте минус 37.

Транспорт: комментарий `<!--L2SIZE:03200258-->` перед HTML в обычном пакете `NpcHtmlMessage` (0x0F), где два четырёхзначных числа записаны в шестнадцатеричном виде. Остальные поля пакета не меняются. Обычный клиент не получает поддержку изменения размера от одного лишь серверного обновления.

Клиент: `client/source/system/nwindow.dll` и `client/build/system/nwindow.dll` содержат патч. Исходные DLL сохранены рядом с суффиксом `.pre-dialog-size.bak`. Пересборка `interface.u` не требуется. Патч проверяет SHA256 исходной DLL, добавляет секцию с независимым от адреса загрузки кодом и перехватывает загрузку NPC HTML. Он хранит исходные размеры двух нативных NPC viewers, проверяет заголовок и диапазоны и меняет рамку и внутренний viewer перед разбором HTML.

Инструменты находятся в `D:\Lineage\tools`. Повторная сборка в отдельный файл:

```bat
tools\vendor\python\python.exe tools\client\patch_npc_dialog_size.py client\source\system\nwindow.dll.pre-dialog-size.bak tools\client\nwindow-sized.dll
tools\vendor\python\python.exe tools\client\test_npc_dialog_size.py
tools\vendor\ant\bin\ant.bat -f source\aCis_gameserver\build.xml
```

Проверено: компиляция сервера; исполнение машинного кода готовой PE DLL в Unicorn с подменёнными нативными методами; размеры 800×600 и 1920×1080; возврат исходных размеров; отклонение повреждённого заголовка и размеров вне диапазона; баланс стека.

Первый вариант патча оказался визуально некорректным: статичные текстуры не заполняли увеличенное окно. Добавлен адаптер отрисовки `tools/client/npc_dialog_render.py`: для связанного с NPC-диалогом элемента он делит выходящий за границы текстуры прямоугольник на девять частей, сохраняя углы. Остальные окна и корректные исходные прямоугольники проходят без изменений. Дополнительные проверки исполняют этот адаптер из готовой PE DLL и проверяют покрытие без разрывов, координаты текстуры и баланс стека.

При отрисовке используются исходные видимые размеры окна, а не полный размер текстуры: последний может включать прозрачные поля. Верхний заголовок пересчитывается отдельно через размер дочернего элемента рамки.

Проверка в игре 2026-11-23: на снимках подтверждены цельный фон, состыкованная полоса прокрутки и заголовок по ширине окна. Пользователь подтвердил работу размеров 800×600 и 500×350, прокрутки, возврата стандартного размера и крестика закрытия. Проверка всех остальных окон клиента и всех разрешений экрана не проводилась.
